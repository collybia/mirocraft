# CLAUDE.md — контекст проекта

## Что это за проект

**Mirocraft** — open-source self-hosted панель управления Minecraft-серверами — аналог Aternos, но без ограничений.
Пользователь ставит панель на свою VPS одной командой и получает веб-интерфейс, где может
создавать серверы с любыми ядрами, модами и плагинами.

Ключевые отличия от конкурентов (Pterodactyl, Crafty, PufferPanel):
- Установка одной командой (Ubuntu: bash-скрипт, Windows Server: PowerShell-скрипт)
- Discord- и Telegram-боты из коробки
- Полноценный REST API — веб-панель и боты являются его клиентами
- Полный набор ПО как у Aternos:
  - Java-ядра: Vanilla (release + snapshot), Paper, Spigot, Purpur, Pufferfish, Folia,
    Fabric, Quilt, Forge, NeoForge, Sponge, гибриды (Mohist, Arclight)
  - Bedrock: Bedrock Dedicated Server, PocketMine-MP, PowerNukkitX
  - Прокси: Velocity, BungeeCord, Waterfall
  - Модпаки: установка в один клик из Modrinth и CurseForge
  - Geyser+Floodgate одной галочкой — Bedrock-игроки заходят на Java-сервер
- DNS/SSL из коробки: бесплатный поддомен (deSEC/DuckDNS) или свой домен (Cloudflare API),
  SRV-записи для Java, автопродление сертификатов

## Архитектура (кратко)

Подробно — см. docs/ARCHITECTURE.md. Главное:

- **daemon/** — ядро на Go. Управляет жизненным циклом серверов через абстракцию Runner:
  - DockerRunner (Linux, приоритетный путь)
  - ProcessRunner (Windows Server и Linux без Docker — нативный запуск Java-процессов)
- **api/** — REST API поверх демона (в том же Go-бинарнике). Аутентификация по токенам.
- **web/** — веб-панель (SPA), клиент API
- **bots/discord/**, **bots/telegram/** — боты, тоже клиенты API
- **installer/** — скрипты установки install.sh и install.ps1

## Жёсткие правила

1. Вся логика управления серверами живёт ТОЛЬКО в демоне. Боты и веб никогда не работают
   с файлами/процессами напрямую — только через REST API.
2. Любой код, зависящий от ОС, изолируется за интерфейсами. Никаких `runtime.GOOS == "windows"`
   размазанных по коду — только в реализациях Runner и в платформенных пакетах.
3. Один Go-бинарник = демон + API + раздача статики веб-панели. Установка не должна требовать
   nginx, внешней БД или отдельных сервисов. БД — SQLite (modernc.org/sqlite, без CGO).
4. Кросс-компиляция обязана работать: `GOOS=linux` и `GOOS=windows` собираются без CGO.
5. Секреты никогда не хардкодятся и не логируются. Токены — только хэши в БД.

## Соглашения по коду

- Go 1.22+, стандартный layout: cmd/, internal/, pkg/
- Ошибки оборачиваем с контекстом: `fmt.Errorf("starting server %s: %w", id, err)`
- Логирование — log/slog, структурированное
- Тесты рядом с кодом, `*_test.go`; для Runner — интеграционные тесты с build tag
- Коммиты — Conventional Commits (feat:, fix:, docs:, refactor:)
- Комментарии и документация кода — на английском; README и пользовательские доки — RU + EN

## Темы оформления (веб-панель)

Панель мультитемная — не «тёмная/светлая», а произвольное число тем.
Подробности реализации — docs/ARCHITECTURE.md, раздел «Веб-панель → Темы».

1. **Только CSS-переменные.** Вся палитра объявлена на `:root`
   (`--bg`, `--bg-elevated`, `--text`, `--text-muted`, `--accent`, `--accent-hover`,
   `--success`, `--warning`, `--danger`, `--border` и т.д.). В компонентах не должно
   быть ни одного захардкоженного цвета — ни hex, ни `rgb()`, ни цветовых утилит
   Tailwind вроде `bg-gray-900`. Только `var(--...)` (через токены в tailwind.config).
   Это правило проверяется линтером и падает в CI.
2. **Новая тема = один файл.** `web/src/themes/<name>.css` переопределяет переменные,
   и больше ничего. Добавление темы не должно требовать правки ни одного компонента.
   Если для темы понадобилось трогать компонент — значит, не хватает переменной:
   заводи переменную, а не исключение.
3. **Контраст.** Каждая тема обязана проходить WCAG AA для текста
   (4.5:1 для обычного, 3:1 для крупного и для границ элементов управления).
   Проверка автоматическая, в тестах — новая тема без проверки не мержится.
4. **Никакого FOUC.** Тема применяется до первого рендера (inline-скрипт в index.html
   читает кэш из localStorage), серверное значение из профиля догружается следом
   и синхронизирует кэш. Переключение темы не должно вызывать мигания.
5. **Консоль тоже темизируется.** Цвета подсветки логов (ошибки, варнинги, debug,
   таймстемпы) — такие же переменные и подпадают под требование контраста.

## Команды

Бинарник и CLI называются `mirocraft`. Пакет cmd/mirocraft.

```
make build        # собрать бинарник под текущую ОС
make build-all    # кросс-компиляция linux/amd64, linux/arm64, windows/amd64
make test         # go test ./...
make lint         # golangci-lint run
make dev          # запуск демона в dev-режиме с hot-reload веба
```

## Как работать над проектом

- Текущий план и порядок задач — docs/ROADMAP.md. Работаем строго по фазам, не забегая вперёд.
- Дизайн API — docs/API.md. Меняешь эндпоинт — обнови этот файл в том же коммите.
- Перед началом задачи прочитай соответствующий раздел ROADMAP и отметь задачу после завершения.
- Если задача требует решения, не описанного в доках — сначала предложи решение и дождись
  подтверждения, потом пиши код.
