# Безопасность

Панель Minecraft-серверов — это по устройству веб-интерфейс, который запускает
чужой код (моды и плагины) на чужой машине и торчит в интернет. Этот документ
описывает, что панель считает границей, а что нет, и что нашёл аудит по задаче
7.2 ROADMAP.

## Как сообщить об уязвимости

Через **GitHub Security Advisories** репозитория
(`Security` → `Report a vulnerability`), а не публичным issue: приватный черновик
виден только вам и мейнтейнеру, пока не выйдет исправление.

Пожалуйста, приложите версию (`mirocraft -version`), способ воспроизведения и то,
что именно получает атакующий. Ответ — в течение недели.

## Модель угроз

Панель защищает:

- **Хост от пользователей панели.** Пользователь с учётной записью может писать
  файлы в каталог своего сервера и запускать там Java. Он не должен уметь читать
  и писать вне этого каталога, исчерпать диск или заставить демон ходить туда,
  куда он сам не дотягивается.
- **Пользователей друг от друга.** Чужой сервер для пользователя не существует:
  запрос к нему отвечает 404, а не 403, чтобы нельзя было перебором узнать, какие
  серверы есть.
- **Учётные записи от кражи токена.** Токены хранятся хэшами, сессии живут сутки,
  смена пароля обрывает остальные сессии.

Панель **не** защищает:

- **Оператора от того, что он запускает.** Плагин или мод — это произвольный
  Java-код с правами процесса сервера. Это природа задачи: панель, которая не даёт
  ставить моды, не панель. Изоляция здесь — дело Docker (`runner.type: docker`),
  и это причина ставить его.
- **От того, кому вы дали админа.** Администратор может всё, включая чтение
  файлов любого сервера.

## Что защищает и как

| Поверхность | Что сделано |
|---|---|
| Пароли | bcrypt; минимум 10 символов; сравнение с фиктивным хэшем для несуществующего логина, чтобы по времени ответа нельзя было перебирать логины |
| Токены | 256 бит из `crypto/rand`, в БД только SHA-256; префикс `mcr_`, чтобы утёкшая строка узнавалась сканерами секретов |
| Сессии | TTL сутки; смена пароля обрывает остальные сессии, сброс пароля админом — все; заблокированный пользователь отвергается на каждом запросе, а не при следующем входе |
| Скоупы | у токена есть список прав, `admin:*` покрывает всё; сессионные токены **не** получают `integrations:act` |
| Делегирование ботами | заголовок `X-Mirocraft-On-Behalf-Of` действует только для токена с `integrations:act` (проверяется буквально, в обход `admin:*`) и ограничен `DelegatableScopes`; на `/admin/*` отвергается совсем |
| Файлы | всё через `internal/fileman`: канонизация пути, запрет `..`, абсолютных форм и Windows-ловушек; символьные ссылки при распаковке пропускаются |
| Архивы | 100 000 записей, 1 ГиБ на файл, 8 ГиБ на распаковку суммарно, считается по записанному, а не по заявленному в заголовке |
| Модпаки | загрузка только по https и только с хостов реестров; пути из индекса и из архива проходят ту же проверку; сверка sha512/sha1 |
| Вебхуки | адрес пользовательский, поэтому отказ на приватные и link-local адреса — и при проверке имени, и **в момент подключения**, чтобы DNS-ребиндинг не проходил между двумя резолвами; включается `webhooks.allow_private_hosts` |
| Диск | на аккаунт — `max_disk_mb` (0 — без лимита), считаются каталоги серверов и бэкапы |
| Rate limit | 120 запросов в минуту на токен, 5 попыток входа в минуту на IP |
| Консольные команды | имена игроков валидируются строго (3–16, `[a-zA-Z0-9_]`) — они попадают в консольную команду |
| WebSocket | одноразовый тикет с TTL 30 с вместо токена в URL; проверка Origin по умолчанию same-origin |
| SQL | только параметризованные запросы |
| Браузер | `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: no-referrer`, CSP на панели и на API |
| Секреты на диске | БД `0600`, `initial-admin.txt` `0600`, конфиг `0640` root:mirocraft, каталог данных `0750` |
| Зависимости | `govulncheck` и `npm audit` в CI; на момент аудита — 0 достижимых уязвимостей и 0 в панели |

## Что аудит нашёл и что с этим сделано

**Смена пароля не обрывала сессии.** Украденный сессионный токен продолжал
работать сутки после того, как владелец сменил пароль именно затем, чтобы его
отобрать. Теперь смена пароля удаляет остальные сессии аккаунта (текущую —
оставляет, иначе это читается как «не сработало»), а сброс пароля админом —
все. API-токены не трогаются: это отдельные, перечисленные в панели и отзываемые
по одному учётные данные, и ломать все скрипты аккаунта смена пароля не должна.

**Распаковка архива не имела суммарного потолка.** Ограничения были на число
записей и на размер файла; их произведение — это 100 ТБ, то есть диск. Добавлен
общий бюджет в 8 ГиБ, считаемый по фактически записанному: соврать в заголовке о
размере — это и есть zip-бомба.

**`max_disk_mb` хранился, показывался в админке и никогда не применялся.**
Лимит, в который оператор верит и которого у него нет, хуже отсутствия лимита.
Теперь он проверяется перед загрузкой файла, записью из редактора, распаковкой,
установкой дополнения, установкой модпака и созданием бэкапа. Измерение
кэшируется на 30 секунд — это сознательный люфт: аккаунт на пределе может
превысить его на то, что успеет записать за эти секунды, и лимит, опаздывающий на
полминуты, стоит несравнимо больше лимита, которого нет. При `0` (по умолчанию,
и это конфигурация одного пользователя) не выполняется ни одного обхода каталогов.

**Заголовков безопасности не было.** У панели есть кнопки, которые в один клик
останавливают и удаляют сервер, — ровно то, ради чего существует clickjacking.
Добавлены `X-Frame-Options`, `frame-ancestors 'none'`, `nosniff`,
`Referrer-Policy: no-referrer` и CSP. HSTS сознательно нет: заметная доля
установок работает с самоподписанным сертификатом, и HSTS превращает «всё равно
перейти» в тупик для панели, которая прекрасно доступна. Это заголовок для
развёртывания с настоящим сертификатом, а не для кода, который шлёт его всегда.

**Проверка адреса вебхука проверяла имя, а подключался клиент отдельно.** Между
двумя резолвами имя, чьим DNS управляет атакующий, может сменить ответ: публичный
адрес для проверки, `127.0.0.1` для запроса. Проверка перенесена туда, где её
нельзя обогнать, — на адрес, к которому реально идёт подключение (`Dialer.Control`).
Заодно список расширен: помимо RFC 1918 и loopback теперь отвергаются link-local
(там cloud-инстанс держит свои учётные данные), unspecified и CGNAT.

**Аудит смотрел только на Go.** `govulncheck` ничего не знает про npm, а панель —
это тоже код, который выполняется, только в чужом браузере. `npm audit` нашёл
high в `react-router-dom` — открытый редирект, ведущий к XSS. В нашем коде он
недостижим: все переходы в панели — литералы, кроме `/servers/${id}`, где id
приходит из нашей же базы. Но «недостижимо сегодня» — это не «исправлено», и
зависимость обновлена: `react-router-dom` 7, `vite` 8 (там был свой high в
dev-сервере), `postcss`, `playwright`. Стало 0 уязвимостей, и `npm audit`
добавлен в CI, чтобы следующая приходила не через полгода, а в тот же день.
Панель после обновления проверена браузерным e2e целиком: 47 проверок, включая
все темы, FOUC, файлы, каталог, бэкапы и админку.

**Файл БД не имел явных прав.** В нём — хэши паролей и токены ботов, которые
приходится хранить в виде, который можно предъявить Discord. Теперь `0600`,
до включения WAL, чтобы права унаследовали и его файлы-спутники.

## Что проверено и оказалось в порядке

- Обход каталога в файловом менеджере, в распаковке архивов, в установке
  модпаков и в установке дополнений — везде через одну песочницу, с тестами.
- Авторизация на каждом маршруте: серверные ручки идут через `authorizeServer`,
  который проверяет и скоуп, и владельца, и отвечает 404 на чужой сервер.
- CSRF: панель хранит токен в `localStorage` и шлёт его заголовком; cookie в
  проекте нет вообще, поэтому браузер ничего не приложит сам.
- XSS: React экранирует, `dangerouslySetInnerHTML` в проекте нет ни одного.
- Утечка секретов в логи: ни один токен и ни один пароль не попадает в
  структурированный лог; пароль первого админа печатается в stdout и пишется в
  файл `0600`, и это отдельно объяснено в коде.
- Токен бота через API не возвращается — только `configured` и последние четыре
  символа.
- `govulncheck`: 0 достижимых уязвимостей. Одна нашлась в
  `golang.org/x/crypto/openpgp` (GO-2026-5932, «unsafe by design, не
  поддерживается»), но этот пакет не вызывается ни из нашего кода, ни из наших
  зависимостей — он просто присутствует в модуле, и исправленной версии не
  существует в принципе.

## Что знать оператору

- **X-Forwarded-For не учитывается.** Без списка доверенных прокси любой клиент
  может его подделать и обойти лимит входов, поэтому лимит считается по адресу
  соединения. Следствие: если панель стоит за обратным прокси, все запросы
  выглядят приходящими с адреса прокси, и лимит входов становится общим. Панель
  рассчитана стоять первой; за прокси ставьте лимит на самом прокси.
- **Docker — это изоляция.** `runner.type: docker` запускает каждый сервер в
  контейнере с ограничением памяти; нативный запуск процессов даёт серверам права
  того пользователя, под которым работает демон.
- **Бэкап панели — это каталог данных.** В нём и БД с токенами, и миры; храните
  его так же, как хранили бы пароли.
- **Секреты DNS-провайдера лежат в конфиге.** Установщик кладёт его `0640`
  root:mirocraft. Если правите руками — не ослабляйте права.
