# Как этим пользоваться

1. Создай пустой репозиторий на GitHub, склонируй его.
2. Скопируй в корень: CLAUDE.md, папку docs/ (ARCHITECTURE.md, ROADMAP.md, API.md).
3. Запусти `claude` в директории репозитория.
4. Первый промт — ниже. Дальше каждую сессию начинай с короткого промта из раздела
   «Промт для последующих сессий».

---

## Промт для первой сессии

```
Прочитай CLAUDE.md, docs/ARCHITECTURE.md, docs/ROADMAP.md и docs/API.md.

Выполни задачу 0.1 из ROADMAP: инициализируй репозиторий.

Требования:
- go.mod (модуль назови по URL репозитория), Go 1.22+
- Структура: cmd/mirocraft/main.go (пока просто запускает заглушку демона и печатает версию),
  internal/daemon, internal/runner, internal/api, internal/store — с doc.go в каждом пакете,
  описывающим назначение пакета
- Makefile: build, build-all (linux/amd64, linux/arm64, windows/amd64, CGO_ENABLED=0),
  test, lint, dev
- .golangci.yml с разумным набором линтеров
- .gitignore для Go + Node
- GitHub Actions workflow: на push и PR — lint, test, build-all
- Убедись, что make build-all реально собирает все три платформы

Когда закончишь: отметь задачу 0.1 в docs/ROADMAP.md как выполненную и сделай коммит
в стиле Conventional Commits.
```

---

## Промт для последующих сессий

```
Прочитай CLAUDE.md и docs/ROADMAP.md. Выполни задачу X.Y.
Перед написанием кода кратко опиши план (файлы, которые создашь/изменишь) и жди моего ок.
После завершения: тесты зелёные, задача отмечена в ROADMAP, коммит по Conventional Commits.
```

Подставляй номер задачи. Правило «сначала план, потом код» экономит кучу времени
на больших задачах — не пропускай его.

---

## Советы

- Одна задача = одна сессия. Не проси «сделай фазу 2 целиком».
- Если Claude Code предлагает отклониться от ARCHITECTURE.md — либо соглашайся и проси
  обновить доку в том же коммите, либо возвращай к доке. Дока и код не должны расходиться.
- Периодически запускай сессию «прочитай весь код в internal/ и найди расхождения
  с docs/ARCHITECTURE.md и docs/API.md» — это дешёвый аудит.
- ProcessRunner на Windows (задача 1.6) тестируй на реальном Windows Server или
  в виртуалке — кросс-компиляция проверяет только сборку, не поведение.
```
